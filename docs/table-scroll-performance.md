# 多列作业表格滚动性能验证

2026-09-18，本地 Edge，1500 × 950 视口，58 个业务列，部分列包含自定义标签渲染。

## 调整范围

- 全局浮动滚动条不再遍历拥有独立滚动条的表格视口、原生滚动区域和滚动条节点。
- 滚动条坐标 CSS 变量放在轨道上，避免根节点变量继承导致整个表格样式重新计算。
- 自动列宽集中准备测量节点、集中读取布局，只测量新挂载的单元格；换数据或列配置时重新计算。
- 虚拟滚动复用窗口内已有行的元素，数据、插件状态、列布局及事件回调改变时清除缓存。
- 自定义单元格布局检测批量执行；不可展开的 Typography 省略文本由 CSS 处理，不创建溢出观察器。

## 回归

运行 `scripts/test-table-scroll-performance-browser.cjs`，参数为已安装 Playwright 的 node_modules 目录。测试需要本地文档服务运行在 4173 端口。

每种模式先等待首次挂载、布局与观察器执行完成，再连续改变横纵向滚动位置。下表记录两次动画帧之间的等待耗时，不能解读为精确帧率；不同设备结果会不同。

| 行数 | 虚拟滚动 | 连续滚动耗时范围 | 12 次滚动新增测宽节点 |
| --- | --- | --- | --- |
| 100 | 开 | 14–41 ms | 41 |
| 100 | 关 | 12–28 ms | 0 |
| 500 | 开 | 15–39 ms | 41 |
| 500 | 关 | 17–61 ms | 0 |

500 行非虚拟模式仍会首次创建约 29,500 个单元格，首次挂载成本未包含在连续滚动数据中。

`test-table-ellipsis-browser.cjs` 通过：标签行内显示、省略号、显式多行及调宽后的溢出更新。
