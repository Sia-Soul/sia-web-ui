# 图标视觉规范与检查

框架图标使用圆润轮廓、协调比例和统一描边。外框以及可见折角直接使用曲线，圆端描边不能替代外轮廓圆角。箭头、文字编辑符号、数据图表与游戏物品保留各自的语义和方向。

## 尺寸与比例

- SVG 使用 24 单位画布，主体最长边归一化为 18 单位，等比缩放并居中；主体边界不包含描边。
- 默认描边为画布中的 1.8 单位，圆端、圆连接。路径归一化时补偿描边，最终仍随 `size` 等比变化。
- 文件、书本、设备等保留自然宽高比，不强制所有图标成为正方形；检查是否过窄、过扁或视觉体积明显不足。
- 使用 16、24、32px 检查轮廓识别度。大尺寸可见的圆角不能以小尺寸的抗锯齿效果代替。

## 内部符号与组合关系

- 圆圈、方框中的勾号与加号按内容区中心配平。带页签、折页或标题栏的图标，应扣除这些区域后确定内部符号位置。
- 外挂箭头、状态标记可以不在整个图标中心，但应与主体保持清楚的间距，不穿过正文线或轮廓。
- 比较左右、上下留白及视觉重心；整体包围盒居中不代表子符号居中。
- 同系列切换状态保持主体路径、位置和比例一致，例如音量开启与静音。内部明暗对比沿用主题变量，不写死背景填充色。
- 避免重复描画相同线段、断开的连接节点及小尺寸下粘连的细节。

## 本轮全量检查

覆盖 `ICON_NAMES` 的 231 个线框图标和 `FILLED_ICON_NAMES` 的 28 个实心变体，共 259 项。逐页对照 16px 和 32px 图谱，示例页另外提供 24px 对照。

修正范围包括通用轮廓、方向与布局、文件及业务单据、编辑器、图表、设备、多媒体、商店与消息、交通、游戏物品和实心变体。保留原有公开名称与用途；统一的是视觉规范，不要求所有图标重新绘制。

## 验证工具

`scripts/audit-icons.cjs` 使用浏览器渲染全部图标，生成浅色/深色逐页对照图及测量 JSON，校验完整覆盖、主体尺寸、居中、描边和静态边界同步，同时检查代表性子符号的位置及音量状态主体一致性。默认输出到 `logs/icon-audit`，可通过 `--output=目录` 指定审校产物位置。

修改路径后，显式运行 `--write-bounds` 更新 `iconBounds.ts`，再不带该参数运行以验证归一化后的最终几何。该工具只在开发检查时运行，组件没有逐帧测量或运行时路径转换。

几何检查不能代替视觉检查：必须查看全部对照图，确认轮廓、内部留白、语义与主题对比，并在使用这些图标的实际组件中抽查。
